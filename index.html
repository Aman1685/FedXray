          NIH ChestX-ray14

          A large public collection of frontal chest X-rays from the NIH Clinical Center. One image can carry several of 14 thoracic disease labels, so the task is multi-label classification.

          Dataset information

          Things to know before reading results

          • Labels were extracted from radiology reports with text mining, so some are imperfect.
          • An image can have several labels, or none of the 14 (the dataset calls this "No Finding").
          • The labels are very unevenly represented, so accuracy alone can hide poor results on rare labels.

            IID and non-IID data across clients

            In federated learning the data stays with each client, so how it is divided matters.

            IID

            Independent and identically distributed. Every client holds a random sample of the whole dataset, so each client's label mix looks like the overall mix. Averaging their updates works smoothly.

            Non-IID

            Each client's label mix differs, as it would between hospitals with different patients and equipment. Local models pull in different directions (client drift), which can slow FedAvg down. FedProx limits the drift with a proximal term.

            Bars show the share of four example labels on each client. This illustrates the idea and is not real project data.

            How federated learning works

            Instead of collecting every hospital's X-rays in one place, federated learning sends the model to the data. Each site trains locally, and a server combines what the sites learned.

              Aggregation on the server

              Weighted by how much data each client has

              Move the sliders to see how much each client counts in the average. These are example sizes, not project data.

              global weights = Σ (nk ÷ n) × wk

              nk = samples on client k, n = total samples, wk = weights returned by client k. Percentages are rounded.

              FedAvg and FedProx

              Same server step, different local training objective

              FedAvg

              Each client runs several epochs of local training on its own data. The server then averages the resulting weights, weighted by client dataset size (McMahan et al., 2017).

              local loss = Fk(w)

              FedProx

              Like FedAvg, but the local loss gets a proximal term that penalises moving far from the current global model. This keeps clients with different data from drifting apart (Li et al., 2020).

              local loss = Fk(w) + (μ / 2) · ‖w − wglobal‖²

              FedAvgFedProx
              Local objectiveThe client's own lossThe client's own loss plus a proximal penalty
              Server aggregationWeighted averageWeighted average (the same)
              Extra settingNone beyond the usual local training settingsProximal strength μ (μ = 0 gives FedAvg)
              StrengthSimple and communication-efficientMore stable when client data or local work differs
              Watch out forClient drift on non-IID dataμ needs tuning; too large slows local learning
